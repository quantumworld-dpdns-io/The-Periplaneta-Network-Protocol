# WS-B — swarm-gen and api-gateway

Two Rust services. Both code strictly against `proto/WIRE.md`; the frame
codecs live in each crate's `src/wire.rs` and are unit-tested against the
byte offsets in WIRE §4.

```
swarm-gen ──SwarmBinFrame──▶ swarm.bins ──▶ feature-worker ──FeatureFrame──▶ neuro.features ─┐
   ▲  └──JSON──▶ swarm.truth                                      neuro.alerts ─┤
   │                                                                            ▼
interventions ◀──JSON── api-gateway ◀── POST /interventions      api-gateway ──▶ /ws/grid, /ws/node/{id}
                                                     hil.raw ──▶ api-gateway ──▶ /ws/node/ffff000x (binary passthrough)
```

## Prerequisites

- Rust 1.98 (stable-msvc on Windows), CMake (librdkafka is built from source
  via the `cmake-build` feature; MSVC 2022 Build Tools on Windows).
- Infra: `docker compose -f deploy/docker-compose.yml up -d redpanda topics-init`
  (Redpanda on `localhost:19092`, topics created per WIRE §3).

Windows note: `services/api-gateway/.cargo/config.toml` sets `target-dir = "t"`.
MSBuild's `.tlog` paths for the librdkafka build exceed `MAX_PATH` under the
default `target/` on this repo path; the shorter directory avoids that.

## swarm-gen

Run natively (from repo root; matches the `just swarm-run` recipe):

```bash
cd services/swarm-gen && SWARM_NODES=100000 cargo run --release
```

| Env / flag | Default | Meaning |
|---|---|---|
| `SWARM_NODES` / `--nodes` | 100000 | virtual twins, ids `0..N-1`, grid `x = id % GRID_W`, `y = id / GRID_W` |
| `SWARM_SHARDS` / `--shards` | 100 | one `SwarmBinFrame` per shard per bin, key = shard decimal string |
| `BIN_MS` / `--bin-ms` | 100 | bin length |
| `SEED` / `--seed` | 42 | all twin parameters and dynamics are deterministic given seed + interventions |
| `KAFKA_BROKERS` | `localhost:19092` | |
| `GRID_W` / `GRID_H` | 400 / 250 | |
| `METRICS_PORT` | 9100 | Prometheus text at `/metrics` |
| `TWIN_PARAMS` | `../../ml/artifacts/twin_params.json` | WS-C fit; falls back to built-in defaults if absent |
| `SIM_THREADS` | 0 (= all cores) | OS threads used to step shards each bin |
| `SPEED` | 1.0 | wall-clock pacing; `0` = as fast as possible (offline dataset generation) |
| `DURATION_S` | 0 (forever) | stop after N simulated seconds |
| `KAFKA_COMPRESSION` | `lz4` | librdkafka `compression.type` for `swarm.bins` |
| `DRY_RUN` / `--dry-run` | false | simulate only, no Kafka |

Twin model (`src/twin.rs`): per node a gamma-renewal ISI process
`ISI = refractory + Gamma(k, θ)` with per-node `(k, rate, refractory)` drawn
from `twin_params.json`. **`rate_hz` in a unit is the gamma rate parameter (1/θ), not the firing rate**; the firing rate is `mean_rate_hz`, derived as `1/(refractory_s + shape/rate_hz)` when absent (`UnitParams::firing_rate_hz`). Before 2026-09-10 swarm-gen read `rate_hz` as a firing rate, so twins with shape < 1 fired too slowly and shape > 1 too fast. Accepted JSON shapes:

```json
{ "units": [ { "shape": 2.1, "rate_hz": 12.3, "refractory_ms": 2.0, "mean_rate_hz": 5.7 }, ... ], "source": "zenodo-locust" }
```
or marginals
```json
{ "shape": {"dist":"lognormal","mu":0.7,"sigma":0.3},
  "rate_hz": {"dist":"uniform","min":5,"max":40},
  "refractory_ms": {"dist":"const","value":2.0} }
```
Defaults if the file is missing: shape U(1.5, 3), rate U(5, 40) Hz,
refractory 2 ms.

Spikes are generated by stepping each node's precomputed next-spike time
through the bin (no per-spike allocation); 100k nodes at ~22 Hz mean is
~2.2 M gamma draws/s, spread over all cores with `std::thread::scope`.

Intervention dynamics (WIRE §5 → per-node mode switch when the radial wave
from the target origin reaches the node at `t0 + (d/r)·spread_ms`):

| kind | rate multiplier over `τ = (t − t_arrive)/onset_ms` | ISI shape (CV) |
|---|---|---|
| toxin | decays to `(1−intensity)²` by τ≈1, then keeps collapsing `·exp(−(τ−1)(0.5+1.5·i))` | shape / (1+3i) → CV↑ |
| drug | recovers `mult0 → mult0 + (1−mult0)·intensity` with `1−exp(−2τ)` | back toward baseline |
| radiation | burst `×(1+3i·exp(−4τ))`, then suppression to `1−0.95i` with per-bin Gaussian noise | shape / (1+4i) |
| baseline | relax to intrinsic params | intrinsic |

Ground truth on `swarm.truth` (WIRE §6): `intervention_applied` (node_id =
wave origin) when consumed, `symptom_onset` per node when its rate parameter
has been < 5 % of baseline for ≥ 2 s, `recovered` when a symptomatic node
climbs back above 50 %.

Prometheus: `swarm_frames_produced_total`, `swarm_produce_errors_total`,
`swarm_produce_latency_seconds` (bin dispatch → all shard frames acked),
`swarm_sim_step_seconds`, `swarm_nodes_collapsed`, `swarm_sim_lag_ms`,
`swarm_truth_events_total`, `swarm_interventions_applied_total`.

Tests: `cargo test --release` — deterministic seeds (same seed → same
counts, different seed → different), baseline rate matches parameters,
toxin lowers counts and fires `symptom_onset` exactly once per node ≥ 2 s
after arrival, drug recovers + `recovered` event, baseline resets, radiation
bursts then suppresses, `step_all` (parallel) ≡ `step_shard` (serial), WIRE
byte offsets.

Load test (`just loadtest` → `scripts/loadtest.sh`): runs 60 s at 100k
nodes against `localhost:19092`, then uses `rpk` (via docker, `--network
host`) to read `swarm.bins` high-watermarks and the `feature-worker` group
lag; exits non-zero if fewer than 95 % of the expected frames landed.

## api-gateway

```bash
cd services/api-gateway && API_PORT=18080 cargo run --release
```
(`API_PORT` defaults to 8080, which is the in-container port; on this dev
host 8080 is taken, so run natively with `API_PORT=18080`. Compose maps
`18080:8080`.)

| Env | Default | |
|---|---|---|
| `API_PORT` | 8080 | |
| `KAFKA_BROKERS` | `localhost:19092` | consumer group `api-gateway` on `neuro.features`, `neuro.alerts`, `hil.raw` |
| `GRID_W` / `GRID_H` | 400 / 250 | |
| `SWARM_NODES` | `GRID_W*GRID_H` | ids ≥ this (and non-HIL) are rejected on `/ws/node/{id}` and in interventions |
| `HIL_NODES` | 2 | how many `0xFFFF0000+i` badges to always list |
| `CORS_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | comma list |

Endpoints (WIRE §9):

- `GET /health` → `{"status":"ok","kafka":true|false}` (`kafka` from a 10 s metadata probe / consumer liveness).
- `GET /nodes/hil` → list of HIL nodes with `online` (a `hil.raw` frame seen in the last 5 s), `mode` and `last_seq` taken from the frame header. The MQTT `status` fields (`uptime_s`, `rssi`, `fw`, `ip`) are emitted only when known — there is no Kafka topic for `hil/{id}/status` yet, so they are currently absent (**stub**; the bridge can add a relay topic later).
- `POST /interventions` → validates kind/target/params/source, fills `id` (uuid v4) and `t_ms`, produces to `interventions` keyed by id, returns `202` with the full record; `400` with `{"error":..}` on validation failure, `503` if Kafka is unreachable.
- `GET /metrics` → Prometheus (`gateway_feature_frames_total`, `gateway_alerts_total`, `gateway_hil_frames_total`, `gateway_interventions_total`, `gateway_grid_frames_sent_total`, `gateway_ws_clients`, `gateway_decode_errors_total`).
- `WS /ws/grid` → one text `hello` then binary `GridFrame` at 5 Hz from the in-memory `GRID_W×GRID_H` `Vec<u8>` stress grid (updated from each `FeatureFrame`; unknown nodes are 0).
- `WS /ws/node/{id}` (`id` decimal or 8-hex) → text `{"type":"features",...}` at 1 Hz (state 4/offline and zeros until a FeatureFrame for that node arrives), text `{"type":"alert",...}` on `neuro.alerts` for that node, and for HIL ids binary `HilRawFrame` passthrough.

Smoke test: with the gateway running, `bash services/api-gateway/scripts/smoke.sh`
(curl; WebSocket checks only if `websocat` is installed).

## Docker

Both crates ship multi-stage Dockerfiles (`rust:1-bookworm` builder with
cmake, `debian:bookworm-slim` runtime). Compose entries live in the WS-B block
of `deploy/docker-compose.yml` (`swarm-gen` exposes 9100, `api-gateway`
maps `18080:8080`; `ml/artifacts` is mounted read-only into swarm-gen for
`twin_params.json`).

## Measured on this machine

Laptop dev host (Windows 11, 20 logical cores, Redpanda in Docker Desktop
with `--smp 1 --memory 1G`, compose defaults 100k nodes / 100 shards / 100 ms):

| Run | Result |
|---|---|
| `swarm-gen --dry-run` (no Kafka) | 10.0 bins/s = 1,000 frames/s sustained, `sim_lag_ms` 0; swarm build 6 ms |
| 20 s against `localhost:19092` | 20,000 / 20,000 frames acked, 0 errors, `swarm.bins` high-watermarks sum to 20,000 |
| `DURATION_S=30 scripts/loadtest.sh` with a toxin region r=40 (≈5k nodes) applied | 30,000 / 30,000 frames (~938 frames/s wall incl. startup/flush; 1,000 frames/s steady), 0 errors, lag 0 ms; mean produce latency (bin dispatch → all 100 shard frames acked) 61 ms, p64 < 50 ms, p86 < 100 ms; mean sim step 11.7 ms (4.5 ms at baseline, more while ~5k nodes are in collapse dynamics); 5,026 truth events (1 `intervention_applied` + 5,025 `symptom_onset`) |
| api-gateway `/ws/grid` | 5 Hz `GridFrame` (100,024 B each) verified with a raw WebSocket client; hello JSON per WIRE §4.4 |
| api-gateway `/ws/node/80125` | 1 Hz features text; an alert produced to `neuro.alerts` via `rpk` arrived as `{"type":"alert",...}` on the socket |
| `scripts/smoke.sh` | health / nodes/hil / metrics / POST 202 + 400 / CORS preflight all pass |

Throughput lesson baked into the code: truth events must be produced
concurrently with the shard frames (`tokio::join!` of two `join_all`s). An
early version awaited them one by one and a single toxin wave (3.7k
`symptom_onset` events) stalled the producer ~38 s.

Stubs / known gaps:
- `GET /nodes/hil` fills `online`, `mode`, `last_seq`, `last_seen_ms`,
  `frames` from `hil.raw`; `uptime_s`/`rssi`/`fw`/`ip` (MQTT `status`) are
  absent until mqtt-bridge relays them to Kafka.
- `swarm.truth` is not consumed by the gateway (not needed for §9 endpoints).
- `ml/artifacts/twin_params.json` did not exist at the time of writing; the
  built-in defaults were used for all measurements.
